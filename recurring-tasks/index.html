Recurring Tasks & Issue Scheduler for Jira

Create recurring Jira issues automatically: daily, weekly, monthly or yearly. Runs on Atlassian.

Set a schedule once, and the right Jira issue appears on time, in your time zone, with sub-tasks, labels and a due date. No cron and no Jira Automation quota.

Where to find it

  • Project sidebar → Recurring tasks: schedules for that project.
  • Apps → Recurring Tasks: every schedule you own. Jira admins see every schedule on the site.
  • Issue view → ••• → Repeat this issue: turns an existing issue into a schedule, pre-filled from the issue.

Create a recurring task

  1. Click Create recurring task.
  2. What to create: issue type, summary, description, assignee (unassigned, schedule owner or a specific person), priority, labels, due date offset, parent/epic and sub-tasks (one per line).
  3. When: Daily (optionally weekdays only), Weekly on chosen days, Monthly (on day N, on the first/second/third/fourth/last weekday, or on the last day), or Yearly. Choose Every N, the hour, the time zone, the start date, and optionally an end date or a maximum number of issues.
  4. Check the Preview of the next five runs and click Save schedule.

Placeholders

Use these in the summary, description and labels. Values use the schedule's time zone.

PlaceholderExample
{{date}}2026-10-05
{{day}}05
{{weekday}}Monday
{{week}}41 (ISO week)
{{month}} / {{monthName}}10 / October
{{quarter}}Q4
{{year}}2026
{{count}}12 (occurrence number)

Options

  • Skip a run if the previous issue is still open: prevents a pile-up of identical tasks.
  • Add new issues to the active sprint: uses the first active sprint on a scrum board of the project.

Managing schedules

  • Run now creates the issue immediately without changing the schedule.
  • Pause / Resume: resuming never back-fills missed runs; the next run is calculated from now.
  • History shows every run for 90 days with the created issue, and any warning or error.
  • Delete removes the schedule and its history. Issues it already created stay in Jira.

Timing

Schedules are checked every hour. An issue due at 09:00 is created between 09:00 and about 10:00 local time. Daylight saving time changes are handled automatically: a 09:00 schedule stays at 09:00 local time.

Permissions

  • You can create schedules in projects where you have the Create issues permission.
  • Only the schedule owner or a project admin can edit, pause, run or delete a schedule.
  • Issues are created by the app and the owner is set as reporter when Jira allows it.

Troubleshooting

A run failed. Open History. The message comes from Jira, for example a required field the template does not fill. Edit the schedule, or relax the field configuration.

The issue did not go into the sprint. The project needs a scrum board with an active sprint.

Nothing was created. Check that the schedule is Active, the start date has passed, and the app's licence is active.
